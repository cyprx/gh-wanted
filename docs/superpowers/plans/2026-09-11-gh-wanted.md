# gh-wanted Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task by task after the proposed choices are accepted. Read the spec and applicable AGENTS instructions first. Steps use checkboxes for tracking. This is a review draft, not authorization to implement its proposed choices.

**Goal:** Build a Rust TUI that helps contributors organize watched repositories by GitHub topics and local tags, discover issues, and review daily updates.

**Architecture:** A keyboard-driven UI owns application state. A bounded background worker calls `gh` and returns typed results; a local store holds tags, cached data, and sync checkpoints. GitHub access remains behind a small adapter so tests run without credentials or network access.

**Tech Stack:** Rust and GitHub CLI are agreed. Ratatui with Crossterm, SQLite through rusqlite, serde/serde_json, anyhow, directories, and a date/time library are proposals, not installed or selected dependencies. Resolve compatible versions and the minimum Rust version before scaffolding.

**Spec:** `../../../IDEA.md` relative to this document, at repository root.

## Choices for review before implementation

| Choice | Proposed default | Reason |
| --- | --- | --- |
| TUI | Ratatui + Crossterm | Dedicated terminal rendering and keyboard events |
| Persistence | SQLite in the platform user-data directory | Transactions for tags, cache, and sync checkpoints |
| Accounts | One active github.com account per session, isolated storage by host and user ID | Prevent cross-account cache and tag leakage |
| Repository filter | AND across selected topics and local tags | Matches the agreed `rust` plus `priority` example |
| Tag normalization | Trim, lowercase, deduplicate; reject blank tags | Predictable matching and editing |
| Focus | Named saved repository and issue filters | Makes focus repeatable without adding a task manager |
| Daily view | Today in local time, plus a separate catch-up section since last successful sync | Distinguishes calendar activity from missed updates |
| Initial history | Last 24 hours, visibly labeled | Avoid an unbounded first sync |
| Refresh | Manual refresh plus every 15 minutes while running | Bounded background traffic |
| Read state | Local explicit acknowledgment, independent of sync | Refresh never silently marks items read |
| Initial platform | macOS development and smoke testing; Linux CI when introduced | Matches the current environment |

Do not treat silence as acceptance of these choices. The personal issue shortlist, Windows support, enterprise hosts, and exact release targets remain outside the first milestone. No background daemon or automation is created by this plan.

## Delivery sequence

Build the repository/tag slice first, then issue discovery, then daily updates. Contributions and local Git actions get separate implementation plans after the core is usable. This avoids making one large plan depend on unsettled PR and Git mutation behavior.

### Milestone 1: Watched repositories and local tags

Deliverable: open the TUI, import watched repositories, inspect GitHub topics, edit local tags, and filter the list. Tags survive restart and repository rename.

**Proposed files:**

- `Cargo.toml`, `Cargo.lock`, `.gitignore`: executable package, resolved dependencies, generated-file exclusions.
- `src/main.rs`: startup, terminal lifecycle, exit reporting.
- `src/lib.rs`: module boundary for integration tests.
- `src/app.rs`: navigation state, input modes, worker-result handling.
- `src/github.rs`: typed `gh` adapter and subprocess execution.
- `src/repositories.rs`: repository identity, tags, and filtering.
- `src/store.rs`: schema migration, transactions, local cache.
- `src/ui.rs`: list/detail layout and keyboard help.
- `tests/github_contract.rs`, `tests/store_roundtrip.rs`, `tests/repository_flow.rs`: behavior checks.
- `tests/fixtures/`: synthetic API responses with no real account data.
- `README.md`: prerequisites, running, keybindings, and data location.

**Proposed contracts:**

```rust
struct Repository {
    id: u64,
    full_name: String,
    description: Option<String>,
    topics: Vec<String>,
    archived: bool,
}

struct RepoFilter {
    text: String,
    topics: Vec<String>,
    local_tags: Vec<String>,
}

trait Github {
    fn watched_repositories(&self) -> anyhow::Result<Vec<Repository>>;
}

trait TagStore {
    fn tags(&self, repo_id: u64) -> anyhow::Result<Vec<String>>;
    fn replace_tags(&mut self, repo_id: u64, tags: &[String]) -> anyhow::Result<()>;
}

fn matches(repo: &Repository, tags: &[String], filter: &RepoFilter) -> bool;
```

These are proposed interfaces, not existing APIs. Add account partitioning at the store boundary so repository IDs are always interpreted within the selected account.

- [ ] Accept or revise the choices above, then recheck local instructions, Git status, toolchain, and `gh` availability.
- [ ] Resolve dependency versions and their Rust requirements from official crate documentation. Use a project-local development environment if a toolchain must be provisioned; do not alter global configuration implicitly.
- [ ] Scaffold the executable and an offline fixture mode. Fixture mode uses a temporary store and clearly shows Demo in the UI.
- [ ] Write failing repository-filter tests: topic-only match, local-tag-only match, combined AND, missing topic, empty filter, and repository rename with stable numeric ID.
- [ ] Implement filtering and tag normalization. Keep upstream topics and local tags in separate fields and display them with different prefixes.
- [ ] Write store tests for restart persistence, account isolation, duplicate tag normalization, migration rollback, and rejected/corrupt storage. Never reset damaged storage silently.
- [ ] Implement transactional tag updates and cache replacement. A failed save leaves both disk state and displayed tags unchanged.
- [ ] Add a fake subprocess harness that captures executable and argument vectors. Test two response pages, empty subscriptions, malformed JSON, nonzero exit, timeout, and a missing `gh` executable.
- [ ] Implement `gh` calls using argument arrays with no shell, noninteractive prompting disabled, bounded stdout/stderr capture, and a timeout that kills and reaps the child. Present safe error categories instead of dumping raw process output.
- [ ] Fetch `GET /user` to establish account identity, then `GET /user/subscriptions?per_page=100` with pagination. Deduplicate by repository ID. Validate topic field availability against the real endpoint before adding any per-repository fallback calls.
- [ ] Implement a single bounded sync worker so slow GitHub calls never block key handling. Ignore stale results after a superseding request or account change. Preserve cached rows on errors and label them stale.
- [ ] Render repositories, selected-repository details, topics, and local tags. Support arrows/j/k, Tab, `/` search, `t` tag editing, `r` refresh, `?` help, and `q` quit; editing mode treats text keys as text and Esc cancels.
- [ ] Sanitize terminal control characters in remote text. Handle empty lists, disappearing selections, small terminals, resize, and Unicode without panics. Restore the terminal on exit and errors.
- [ ] Run targeted tests, then formatting and lint checks. Smoke-test fixture navigation and terminal restoration in a PTY. Only then run an authenticated, read-only watched-repository smoke test if credentials are available.

**Acceptance:** Editing tags sends no GitHub write request. Repository topic `rust` plus local tag `priority` returns only repositories satisfying both. Tags persist after restart and rename. A timeout leaves the UI usable with an error and existing cache.

### Milestone 2: Issue discovery and saved focus views

Deliverable: choose a repository set, browse matching issues, and save/reopen the filter as a focus.

**Proposed files:** `src/issues.rs`, `src/focus.rs`, `tests/issue_flow.rs`, and `tests/focus_roundtrip.rs`; extend `github.rs`, `store.rs`, `app.rs`, `ui.rs`, and README.

- [x] Define issue identity as repository ID plus issue number. Store title, state, timestamps, labels, assignees, and URL separately from repository tags.
- [x] Add fixtures that mix issues and PR-shaped records, multiple labels, missing assignees, and duplicate pages. Assert PRs do not appear in the issue feed.
- [x] Fetch paginated repository issues with explicit state and sort parameters. Avoid global search caps for complete per-repository sync; large result sets must show loading/partial status instead of pretending to be complete.
- [x] Implement separate issue-label, keyword, state, and unassigned filters over the selected repository set. Keyword matching is case-insensitive title/body substring matching unless revised during review.
- [x] Store named focus definitions containing repository filters and issue filters, not frozen repository lists. Topic/tag changes are reflected when a focus is reopened.
- [x] Test focus save/reload, duplicate-name handling, changed repository membership, empty matches, and interrupted fetches. Confirm names and filter serialization before implementing persistence.
- [x] Add issue list/detail and focus selection UI. Provide an explicit browser-open action only for validated HTTPS github.com issue URLs. Avoid GitHub writes in this milestone.
- [x] Run issue/focus tests, then a PTY flow from repository selection to saved focus and issue details. Update README with the tested keybindings.

**Acceptance:** A saved `rust` + `priority` focus with issue label `good first issue` restores after restart and reflects current repository membership. Missing pages are visible; no silent truncation or issue/PR mixing occurs.

### Milestone 3: Daily updates and catch-up

Deliverable: see new issues and changed discussions since the previous successful sync, with a local daily grouping and explicit acknowledgment.

**Proposed files:** `src/activity.rs`, `src/sync.rs`, `tests/activity_sync.rs`; extend the GitHub adapter, store, UI, and README.

- [x] Verify the issue, comment, PR, review, and check endpoints and required permissions against official documentation before selecting the exact fetch contract. A changed issue timestamp is not evidence of a maintainer reply or passing CI.
- [x] Model distinct activity kinds for new issue, issue change, comment, PR change, and review. Include source IDs, source timestamps, repository/account identity, and fetched-at time.
- [x] Use explicit author association when available; otherwise call an entry a comment rather than infer maintainer status. Fetch detailed replies/reviews on demand where full polling would be expensive.
- [x] Write deterministic clock-based tests for midnight, timezone changes, equal timestamps, duplicate pages, offline catch-up, and partial endpoint failure.
- [x] Track checkpoints per account, repository, and feed. At sync start capture an upper bound; query with a short overlap, deduplicate by source identity/version, and advance only the successfully persisted feed to that upper bound.
- [x] Commit activity and its checkpoint in one transaction. Failed pages do not advance that feed. A retry neither duplicates entries nor drops boundary events.
- [x] Keep acknowledgment separate from fetch checkpoints. Opening or refreshing the app does not automatically mark new activity read.
- [x] Implement local-time Today grouping and a separately labeled catch-up section. Explain that deleted or inaccessible activity cannot be reconstructed by polling and snapshot changes are not a complete event audit.
- [x] Add the accepted refresh interval with no overlapping syncs. Pause retry loops on auth failures; honor rate-limit retry guidance and retain per-feed error indicators.
- [x] Test a two-session scenario with injected new issue/comment/PR fixtures and a failed repository. Verify successful feeds advance, the failed feed retries, and acknowledged items stay acknowledged.
- [x] Run the targeted sync suite, then the full project checks and an authenticated read-only catch-up smoke test when available.

**Acceptance:** Closing and reopening does not lose updates within the available API history. A failed feed remains visibly incomplete and keeps its old checkpoint. Today and unread are independent concepts.
